# 001.md - Complete Message Namespace Actions

## Current Task
Implement the v0.2 message action surface for `bot.message`: `edit`, `delete`, and `forward`, building on the existing v0.1 `send` and `reply` behavior.

## Scope
- Add or complete `bot.message.edit(...)` for `editMessageText`.
- Add or complete `bot.message.delete(...)` for `deleteMessage`.
- Add or complete `bot.message.forward(...)` for `forwardMessage`.
- Preserve lifecycle checks: active Telegram API calls must raise `BotNotStartedError` before start and `BotStoppedError` after stop.
- Keep wrappers thin and predictable; return Telegram `result` directly.
- Ensure no full bot token is ever logged, repr-ed, or included in exceptions.

## Expected Deliverables
- Production code for message edit/delete/forward methods.
- Unit tests using mocked HTTP client behavior.
- Integration-style namespace tests where feasible without real Telegram network calls.
- Logging at useful debug points: method called, sanitized parameter summary, and failure context.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 001 for the TG Bot event-driven SDK v0.2. First inspect the existing classes and functions to understand their responsibilities before changing code. Use test-driven development: write failing tests that describe the user-visible behavior of `bot.message.edit`, `bot.message.delete`, and `bot.message.forward`, then implement the smallest robust code to pass them. Tests must be feature-driven rather than implementation-driven. Include edge cases such as missing optional parameters, Telegram API errors, lifecycle errors, and token redaction. Add complete logging that helps debugging without leaking secrets. Ensure code is robust, does not create deadlocks, memory leaks, or CPU busy loops, and does not introduce hidden background work. Every async test must have timeout control, and the external test command must also be run under a timeout as a second safety layer. Run the relevant tests and then the full test suite with an external timeout. After all tests pass, commit the changes to git with a clear conventional commit message.
