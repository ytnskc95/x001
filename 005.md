# 005.md - Complete API Error Subclasses and Parameter Handling

## Current Task
Complete the v0.2 error model by mapping Telegram API failures to the full exception hierarchy and preserving response parameters.

## Scope
- Ensure `TelegramAPIError` stores `method`, `status_code`, `error_code`, `description`, `parameters`, and `raw_response`.
- Map HTTP/API conditions to subclasses: bad request, unauthorized, forbidden, not found, conflict, rate limit, and migrate-to-chat.
- Ensure `TelegramRateLimitError` exposes `retry_after`.
- Ensure `TelegramMigrateToChatError` exposes `migrate_to_chat_id`.
- Redact bot tokens from exception messages, repr, logs, and status output.

## Expected Deliverables
- Production code for complete error mapping.
- Tests for every mapped subclass and fallback behavior.
- Tests proving response parameters are preserved and token leakage does not occur.
- Logs with sanitized method/error context.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 005 for the TG Bot event-driven SDK v0.2. First read the existing errors module and HTTP client response handling to understand the intended responsibilities and current behavior. Use test-driven development: write behavior-focused tests for each Telegram API error subclass, including 400, 401, 403, 404, 409, 429 with `retry_after`, migrate-to-chat parameters, malformed error responses, missing parameters, and network/timeout conversion. Tests must verify that no full bot token appears in exception strings, repr output, logs, or status. Add complete logging for API failures that helps debugging while preserving security. Make the code robust against unexpected response shapes, cancellation, and partially available HTTP metadata. Avoid deadlocks, memory leaks, CPU busy loops, and broad exception swallowing that hides failures. Every async test must include timeout control, and the external test command must also be wrapped in a timeout. Run targeted tests and the full test suite under timeout protection. After all tests pass, commit the changes to git with a clear conventional commit message.
