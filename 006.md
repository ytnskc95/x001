# 006.md - Parameterize Transport Reconnect Backoff

## Current Task
Implement configurable transport reconnect behavior for polling: exponential backoff, jitter, and maximum retry behavior.

## Scope
- Add configuration fields for initial backoff, maximum backoff, jitter, and optional maximum retries.
- Apply the policy to network errors and Telegram 5xx responses in the polling transport.
- Preserve special handling: long-poll timeout is normal, 429 sleeps `retry_after`, 401/409 are fatal.
- Emit appropriate system events such as `TRANSPORT_DISCONNECTED`, `TRANSPORT_RECONNECTING`, `RATE_LIMITED`, and `TRANSPORT_FAILED`.
- Ensure no CPU busy loop during repeated failures.

## Expected Deliverables
- Production code for configurable reconnect policy.
- Tests using fake time/sleep or injectable sleep to avoid slow real-time tests.
- Tests for retry limits, jitter bounds, reset after success, fatal errors, and system event emission.
- Debug/info/warning logs for reconnect behavior.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt

Add detailed logging for retry decisions, delay values, state transitions, and fatal failures while redacting tokens.
