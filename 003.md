# 003.md - Implement File Namespace and Download Support

## Current Task
Implement the v0.2 file namespace for `bot.file`: `get_file`, `download`, and download URL/path handling for both official Telegram Bot API and Local Bot API Server behavior.

## Scope
- Implement `get_file(file_id)` using Bot API `getFile`.
- Implement `download(file_id_or_path, ...)` with safe support for bytes/stream output as defined by the project style.
- Build official download URLs as `{api_base_url}/file/bot{token}/{file_path}`.
- Support Local Bot API Server responses where `getFile` may return a local absolute path; allow returning that path or reading bytes/stream according to the API design.
- Ensure token redaction in logs and errors.

## Expected Deliverables
- Production code for file namespace methods.
- Tests for official URL construction, local path behavior, download success, network failures, lifecycle checks, and token redaction.
- Debug logs for file lookup and download flow without leaking token or file contents.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 003 for the TG Bot event-driven SDK v0.2. First study the current HTTP client, configuration objects, raw namespace, and lifecycle checks to understand existing responsibilities. Use test-driven development: write behavior-first tests for `get_file` and `download`, covering official Bot API URLs, Local Bot API Server absolute paths, missing `file_path`, network errors, API errors, and stopped/not-started bot states. Do not use real Telegram network calls. Add comprehensive but safe logging that helps debug URL construction and download failures while redacting the bot token and avoiding file content dumps. Handle boundary conditions carefully: path traversal assumptions, very large files, streaming versus bytes, caller-owned resources, and cancellation. Avoid deadlocks, memory leaks, CPU busy loops, and unbounded in-memory buffering unless explicitly requested by the API. Every async test must have timeout control, and the outer test command must also use a timeout. Run targeted tests and the full test suite under timeout protection. After all tests pass, commit the changes to git with a clear conventional commit message.
