# 004.md - Implement Keyboard Builders and Callback Answers

## Current Task
Implement the v0.2 keyboard namespace: inline keyboard builder, reply keyboard builder, and `answer_callback_query` interaction action.

## Scope
- Provide builder helpers that produce Telegram-compatible `reply_markup` dictionaries.
- Support inline keyboard buttons such as `text`, `callback_data`, `url`, and other fields supported by the thin builder design.
- Support reply keyboard rows, resize/one-time/selective options, and removal/force-reply helpers if consistent with project API style.
- Implement `answer_callback_query` using Bot API `answerCallbackQuery`.
- Keep builders pure and side-effect free.

## Expected Deliverables
- Production code for keyboard builders and callback answer method.
- Tests for generated markup shape, validation boundaries, lifecycle checks for action calls, and API error propagation.
- Useful logs for `answer_callback_query`; builders should avoid noisy logs unless validation fails.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 004 for the TG Bot event-driven SDK v0.2. Inspect the namespace structure, base namespace, raw call path, and current keyboard stubs before writing tests. Use test-driven development: write feature-oriented tests that verify the exact Telegram-compatible markup produced by inline and reply keyboard builders, plus `answer_callback_query` behavior. Include boundary cases such as empty rows, invalid button combinations if validation exists, very long callback data, optional parameters, lifecycle errors, and Telegram API errors. Add logging that is useful for debugging interaction actions while keeping builders deterministic and quiet. Ensure robust code with no hidden shared mutable state, deadlocks, memory leaks, CPU busy loops, or accidental mutation of user-provided structures. Every async test must have timeout control, and the outer test runner command must also use a timeout. Run targeted tests and the full test suite with timeout protection. After all tests pass, commit the changes to git with a clear conventional commit message.
