# 007.md - Add Advanced HTTP Client Configuration

## Current Task
Implement v0.2 advanced HTTP client configuration: proxy, connection pool limits, custom `api_base_url`, and optional external session injection.

## Scope
- Add or complete `HttpConfig` fields for proxy, max connections, base URL, connect timeout, read timeout, and total timeout.
- Enforce `read_timeout > polling.timeout` or automatically derive a safe default as specified.
- Support Local Bot API Server via custom `api_base_url`.
- Support externally supplied HTTP session/client where the SDK must not close caller-owned resources.
- Preserve SDK-owned client lifecycle management.

## Expected Deliverables
- Production code for HTTP configuration and lifecycle handling.
- Tests for timeout derivation, invalid timeout validation, proxy passing, base URL normalization, connection pool setup, external session ownership, and shutdown cleanup.
- Sanitized debug logs for HTTP client creation and close behavior.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 007 for the TG Bot event-driven SDK v0.2. First understand the current `HttpConfig`, Bot lifecycle, HTTP client wrapper, and raw namespace before writing tests. Use test-driven development: write feature-focused tests for timeout derivation from polling timeout, validation of unsafe read timeouts, proxy configuration, max connection configuration, custom API base URL behavior, external session injection, and correct close/no-close ownership semantics. Tests must not make real Telegram calls. Add complete logging around client setup, request configuration summaries, and shutdown, with all tokens redacted. Handle boundary cases such as trailing slashes in base URLs, zero/negative timeout values, cancellation during close, and caller-owned sessions. Avoid deadlocks, memory leaks, CPU busy loops, and leaked sockets/sessions. Every async test must have timeout control, and the external test command must also use a timeout. Run targeted tests and the full test suite with timeout protection. After all tests pass, commit the changes to git with a clear conventional commit message.
