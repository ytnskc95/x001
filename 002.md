# 002.md - Implement Core Media Sending Methods

## Current Task
Implement the v0.2 media namespace core methods for `bot.media`: `send_photo`, `send_document`, `send_video`, `send_audio`, and `send_media_group`.

## Scope
- Support JSON parameters and multipart uploads through the shared raw/HTTP call path.
- Accept Telegram `file_id`, URL strings, and local file-like objects where the existing HTTP client supports file uploads.
- Implement `send_media_group` with correct media array serialization and file attachment handling.
- Keep methods thin wrappers around Bot API methods and return Telegram `result` directly.
- Do not add retries for user-initiated action calls.

## Expected Deliverables
- Production code for media namespace methods.
- Tests for parameter mapping, file upload routing, media group serialization, lifecycle checks, and API error propagation.
- Sanitized debug logging for media actions and failures.

## Mandatory Implementation Requirements
- Add complete logging for debug visibility while redacting secrets.
- Follow test-driven development: write failing tests before implementation.
- First understand the relevant classes and functions; tests must be feature-driven.
- Cover boundary issues and edge cases explicitly.
- Keep code robust, defensive, and maintainable.
- Prevent deadlocks, memory leaks, CPU busy loops, and unbounded resource growth.
- Every async test must use timeout control to avoid infinite blocking.
- Run test commands with an external timeout as a second safety layer.
- Commit changes to git only after all tests pass.

## Prompt
You are implementing task 002 for the TG Bot event-driven SDK v0.2. Begin by reading the existing namespace base class, HTTP client, raw API implementation, and any current media stubs so you understand class and function responsibilities before writing tests. Use test-driven development: create feature-focused tests for sending photos, documents, videos, audio, and media groups, including file-id inputs, URL inputs, file-like uploads, optional captions, and API failure propagation. Tests must not depend on the real Telegram network. Add high-quality logging for debugging while redacting secrets and avoiding large binary payload dumps. Pay close attention to boundary cases, resource cleanup for file handles owned by the caller, multipart encoding, and malformed media group inputs. Avoid deadlocks, memory leaks, CPU busy loops, and unbounded buffering of large files. Every async test must include timeout control, and the overall test command must be wrapped in an external timeout. Run targeted tests and the full test suite with timeout protection. After all tests pass, commit the changes to git with a clear conventional commit message.
